# XN-Interact threat model v0

## T27 browser execution controls

ADR-031 extends the original LinkedIn reader boundary to typed, read-only collection on registered sources. A source binds permitted origins, paths, fields and account identity to a local registration generation. The broker serializes profile ownership and persists normalized records and checkpoint evidence. Interactive authentication remains owner-controlled. Public collection uses a separate profile. Unexpected redirects stop extraction, although Chromium can send redirected requests before Playwright validates the committed URL. Browser writes and browser standing grants remain unsupported. The T27 table row below covers the legacy LinkedIn reader. [Browser security](browser-security.md)

Scope: local personal deployment (Bun stdio server spawned by Claude Code or Codex, SQLite home, OS keyring, operator-owned provider apps, owner approvals at a terminal). Remote multi-user deployment is out of scope.

Assets: provider access and refresh tokens, operator client secrets, vault master key, OAuth state and PKCE verifiers, the owner's public reputation on seven platforms, content drafts and media, workflow journal, approval decisions, provider quotas and paid budgets.

Trust boundaries: (1) host process ↔ XN-Interact over stdio; (2) XN-Interact ↔ provider APIs over HTTPS; (3) browser ↔ transient loopback callback; (4) owner terminal ↔ approval CLI; (5) XN-Interact ↔ XN-Bridge, only through the host.

| T27 | An agent, or injected page content, drives the owner's logged-in Chrome beyond a read, reads credentials from it, reaches another site or a remote browser, or hammers LinkedIn (new) | The reader has no account, no vault entry and no token and is not an OAuth provider. It attaches only to a Chrome debug port that must be plain http on loopback with an explicit port (a remote browser is refused). It builds its own URL from validated parts (LinkedIn Jobs search and the For-you feed only; Instagram is not supported), opens one new tab, scrolls at most twice, reads the accessibility text and closes the tab. `tests/security/web-reader.test.ts` scans the reader file for any click, type, fill, press, mouse, keyboard, cookie, storage, route, header or init-script API and fails if one appears, and checks that only that file imports `playwright-core`. Navigation is limited to https `www.linkedin.com` read-only paths; a login, checkpoint or CAPTCHA page ends the run with `needs_owner` and is never passed. Page text is untrusted data: control characters are stripped, strings are cut to a bound, emails and phone numbers are removed, and nothing from a page is ever executed or used as a URL. Limits: the dedicated Chrome profile keeps the owner's LinkedIn session on disk; whoever can read that profile can use the session, so it must stay in the owner's home directory. LinkedIn's terms restrict automated access and the account can be limited; the caps reduce but do not remove that risk. The page structure can change without notice, which makes the parser return fewer items, not wrong actions. | SEC-03, ROUTE-08, SEC-05 | tests/security/web-reader.test.ts |
